# 웹 접근성 보완 설계

**작성일:** 2026-08-21
**검토 상태:** 시맨틱·상호작용·시각/반응형 독립 검토 반영 완료
**적용 기준:** WCAG 2.2 AA, KWCAG 2.2
**대상:** `index.html`, `styles.css`, `src/app.js`를 중심으로 한 카카오톡 테마 빌더 전체 페이지

## 목표

- 초기 상태와 기본 테마에서 WCAG 2.2 AA 차단 결함을 제거한다.
- 키보드, 스크린리더, 확대·리플로우, 고대비 환경에서도 핵심 제작 흐름을 완료할 수 있게 한다.
- 프리뷰라는 시각적 성격은 유지하되, 모의 UI와 실제 편집 UI를 의미론적으로 분리한다.
- 이후 변경이 화면 밖 포커스, 이름 누락, 대비 저하를 재발시키지 않도록 브라우저 회귀 검사를 저장소에 포함한다.

## 비목표와 경계

- 생성되는 iOS·Android 테마 자체의 네이티브 앱 접근성 인증은 이번 웹 페이지 작업 범위가 아니다.
- 사용자가 지정한 임의 색상과 배경 이미지는 모든 픽셀에서 자동으로 준수를 증명할 수 없다. 이번 계획의 완료 범위는 앱 chrome과 기본 프리뷰의 AA 준수다. 사용자 지정 프리뷰는 사용자 생성 콘텐츠로 명시하고, 계산 가능한 대비 수치·실패 화면·초기화 수단과 `자동 확인 불가` 상태를 제공한다.
- 사용자 색을 임의로 보정하면 다운로드 결과와 프리뷰가 달라지므로 저대비 사용자 색도 비차단 방식으로 유지하고 다운로드를 허용한다. 이 상태는 부분 준수 범위로 문서화하며 axe 0건 완료 조건을 적용하지 않는다. 향후 모든 사용자 조합까지 완전 준수를 강제하려면 실패 색과 판정 불가능한 이미지의 프리뷰 적용 자체를 거부하는 별도 제품 변경이 필요하다.
- 정식 WA 품질인증 또는 장애인 사용자 평가를 자동화 테스트 결과로 대체하지 않는다.

## 검토한 접근 방식

### 1. CSS와 ARIA 속성만 추가

변경량은 작지만 동적 재렌더링 후 포커스 소실, 전역 키보드 충돌, 화면 밖 슬라이드의 실제 탭 순서를 검증하지 못한다. 회귀 방지가 약해 채택하지 않는다.

### 2. 기존 렌더링을 유지하고 접근성 상태를 동기화 — 채택

슬라이드 transform과 현재 UI를 유지하면서 `tab`/`tabpanel`, `inert`, 포커스 의도, 필드 오류, live region을 한 곳에서 동기화한다. Node 단위 테스트와 Playwright/axe 브라우저 테스트를 함께 사용한다. 시각 회귀와 구현 위험의 균형이 가장 좋다.

### 3. 선택한 슬라이드만 DOM에 렌더링

접근성 트리는 단순해지지만 기존 transform 애니메이션, 업로드 상태, 말풍선 상세 상태를 모두 다시 설계해야 한다. 이번 보완 범위에 비해 회귀 위험이 커 채택하지 않는다.

## 설계 원칙

### 앱 UI와 모의 UI 분리

상위 프리뷰 탭·이전/다음·기기 선택·색상·업로드·쇼핑 캐러셀 탐색·말풍선 편집·암호 시뮬레이션은 실제 컨트롤로 유지한다. 검색·설정·하단 탭·메시지 입력처럼 동작하지 않는 휴대폰 내부 요소는 버튼이나 탭 역할을 제거하고 시각 요소로 표현한다. 남는 샘플 콘텐츠는 heading/list/group/선택 상태 또는 짧은 대체 요약 중 한 정책을 페이지별로 명시한다. CSS 배경 이미지는 인접 텍스트가 같은 의미를 제공할 때만 장식으로 처리한다. 실제 링크로 유지할 항목은 목적과 새 창 동작이 이름에 포함되어야 한다.

### 프리뷰 상태의 단일 진실 원천

`setPreviewIndex(index, options)`가 다음 순서를 보장한다.

1. 활성 인덱스 갱신
2. track transform 갱신
3. 탭의 `aria-selected`와 roving `tabIndex` 갱신
4. 패널의 `inert`와 `aria-hidden` 갱신
5. 동적 컬러·업로드·상세 컨트롤 갱신
6. 호출 원인에 따라 포커스 유지 또는 이동

비활성 패널은 flex 너비를 보존해야 하므로 `hidden` 대신 `inert`와 `aria-hidden="true"`를 함께 사용한다.

### 포커스 의도 명시

- 탭 키보드 이동: 선택된 탭으로 포커스 이동
- 이전/다음 버튼: 누른 버튼에 포커스 유지
- 업로드 상세 진입: 상세 제목으로 포커스 이동
- 상세 옵션 변경: 기존 컨트롤 노드를 교체하지 않고 포커스 유지
- 오류·작업 상태: 포커스를 강제로 옮기지 않고 설명 관계와 live region으로 전달

### 상태와 오류의 채널 분리

- 필드 오류: 입력별 고정 도움말·오류 노드와 `aria-describedby`, `aria-invalid`, 필요 시 `aria-errormessage`
- 정상 작업 상태: `role="status" aria-live="polite" aria-atomic="true"`
- 비동기 실패: `role="alert"`
- 암호 시뮬레이션: 숫자를 노출하지 않고 “4자리 중 n자리 입력됨” 전용 status

업로드·생성·실패처럼 이산적인 작업은 live region을 비운 뒤 다음 task에서 다시 기록해 같은 결과가 반복되어도 공지한다. 색상 입력처럼 고빈도인 변화만 행별 결과를 정적으로 갱신하고 요약 상태를 디바운스·병합한다. 이전/다음 버튼은 포커스가 유지되므로 별도 preview status에서 “쇼핑 프리뷰, 4/10”처럼 변경을 알리고, 탭 키보드 이동은 선택된 탭 자체의 발표와 중복되지 않게 한다.

### 대비 처리

- `src/color-contrast.js`에 CSS `#RRGGBB`/`#RRGGBBAA`와 테마 ARGB `#AARRGGBB` 파서를 분리하고, 공통 RGBA 정규화·알파 합성·상대 휘도·대비 계산을 순수 함수로 둔다.
- 기본 팔레트와 정적 CSS 색은 반올림 전 수치로 일반 텍스트 4.5:1, 큰 텍스트·UI 경계 3:1을 통과해야 한다.
- 투명도를 이용해 보조 텍스트를 흐리게 하지 않고, 불투명 색과 크기·굵기·간격으로 위계를 표현한다.
- 각 대비 문맥은 page, 실제 selector, 전경 토큰, 배경 토큰, 영향을 주는 image key, 상태, 기준값을 가진 ledger로 관리한다. 이미지 위 텍스트는 수학적으로 보장되는 scrim이 없으면 `자동 확인 불가`로 표시한다.
- 사용자 지정 색에는 현재 화면 결과와 전체 테마의 최악 비율·실패 화면을 텍스트로 제공한다. 배경색·이미지·페이지가 바뀔 때 관련 문맥을 모두 다시 계산한다.

### 반응형과 사용자 설정

- 760px 이하에서는 고정 footer를 문서 흐름으로 돌려 동적 높이·번역·확대에서도 가림을 방지한다.
- 320 CSS px에서 수평 스크롤과 footer 겹침이 없어야 한다.
- `forced-colors: active`에서 시스템 색상으로 경계·포커스·선택 상태·마스크 아이콘을 유지한다.
- 텍스트 간격 오버라이드와 200%/400% 확대에서 의미 있는 텍스트를 잘라내는 고정 높이·ellipsis를 제거한다.
- `prefers-reduced-motion: reduce`에서는 프리뷰 전환을 즉시 수행한다.

## 검증 구조

- `node --test`: 순수 대비 함수, 기본 팔레트 조합, 키 인덱스 함수, 암호 상태 문자열, 정적 마크업 계약
- Playwright: 실제 accessible name, 탭 순서, 포커스 유지, `inert`, live 상태, 320px 기하, 미디어 쿼리
- axe: 기본 상태와 10개 활성 프리뷰 각각의 자동 검출 가능한 WCAG A/AA 위반
- 수동: VoiceOver+Safari/Chrome, Windows High Contrast 또는 동등한 forced-colors 환경, 200%/400% 확대, WCAG 텍스트 간격

Playwright와 axe는 자동 검출 가능한 일부 문제만 다루므로 수동 완료 게이트를 생략하지 않는다.

## 주요 위험과 완화

- **`inert` 적용 순서:** 대상 패널의 inert를 먼저 해제한 뒤 포커스를 보낸다. 상세 진입 E2E로 고정한다.
- **동적 렌더 포커스:** 상태만 바뀌는 경우 `replaceChildren()`을 금지하고 속성만 동기화한다.
- **기본 팔레트 변경:** 프리뷰와 다운로드 테마가 같은 `defaultThemeState`를 사용하도록 유지하고 iOS/Android 출력 테스트를 함께 갱신한다.
- **사용자 배경 이미지:** 자동 통과로 오판하지 않고 수동 확인 필요 상태로 분류한다.
- **취약한 문자열 테스트:** 마크업 정규식은 구조 계약에만 사용하고 실제 이름·포커스·기하는 브라우저 테스트를 진실 원천으로 둔다.
- **테스트 서버 충돌·파일 변경:** 기존 기본 포트 대신 전용 포트 `43173`을 사용하고 기존 서버를 재사용하지 않는다. 테스트 서버는 `SKIP_ENV_CONFIG=1`로 추적 중인 `src/env-config.js`를 쓰지 않는다.

## 완료 정의

- 앱 chrome과 기본 테마의 10개 프리뷰 상태에서 axe A/AA 위반 0건. 의도적으로 저대비인 사용자 생성 상태는 별도 부분 준수 시나리오로 검사
- 비활성 프리뷰의 접근성 트리·탭 순서 노출 0건
- 모든 실제 컨트롤에 고유하고 문맥적인 접근 가능한 이름 제공
- 키보드만으로 모든 제작·미리보기·다운로드 흐름 수행 가능
- 기본 텍스트 대비 4.5:1 이상, 필요한 UI 경계·상태 3:1 이상
- 320 CSS px, 200%/400% 확대, 텍스트 간격 변경에서 정보·기능 손실 및 footer 겹침 없음
- 단위·브라우저 테스트 전부 통과, console error와 unhandled rejection 0건
- VoiceOver와 고대비 모드 수동 체크리스트 완료
