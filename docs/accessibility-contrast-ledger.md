# 프리뷰 기본 대비 ledger

이 문서는 기본 테마 프리뷰에서 실제로 보이는 텍스트·UI 상태 116개를 페이지별로 추적한다. 자동 판정은 색상 토큰과 명시된 합성 레이어만 계산하며, 계산에는 반올림하지 않은 WCAG 대비값을 사용한다.

이미지 상태는 `cleared`(초기 업로드 없음), `bundled`(저장소 기본 래스터), `user`(사용자 업로드)로 구분한다. 런타임 상태 재정의는 해당 행이 의존하는 이미지 키에만 적용하며, 보호 backing/scrim이 없는 `bundled` 또는 `user` 이미지는 `unknown`으로 남긴다.

axe는 배경 이미지의 픽셀 대비를 판정하지 않으므로 자동 검사 통과를 이미지 대비 증거로 주장하지 않는다. `image` 행과 이미지 위 보호되지 않은 가이드는 수동 픽셀 검수 대상이다. `worst-case-backing`, `worst-case-scrim`, `opaque-backing`은 CSS가 모든 래스터 픽셀을 차단하거나 최악 배경에도 기준을 만족하도록 보장하는 경우에만 자동 판정한다. 각 보증은 행의 `보호 키`에만 적용되며 같은 행의 다른 이미지 키까지 면제하지 않는다. `css-currentcolor-mask`는 PNG 알파가 모양만 제공하고 실제 전경색을 CSS가 칠하는 경우다.

## 판정 경계와 수동 증거

- 자동 PASS는 기본 색상과 선언된 상태의 실제 computed style을 브라우저 테스트에서 대조한 뒤 raw 대비값으로 판단한다. hover, pressed, selected는 테스트가 각 상태를 실제로 활성화한다.
- 탭·테마·암호 점처럼 래스터 자체가 의미 있는 전경인 행, 그리고 말풍선 편집기의 래스터 위 crop/guide 행은 `unknown`이다. 이 항목은 실제 이미지의 최저 대비와 비색상 단서를 수동으로 확인해야 한다.
- 사용자 이미지 업로드 후 색상 진단과 경고 UX는 별도 작업 범위다. 이 ledger는 보호 backing/scrim이 없는 사용자 이미지 상태를 자동 PASS로 승격하지 않는다.
- 채팅 말풍선 backing은 `::before`가 border-image 위에 실제로 칠해지는지 픽셀 표본으로 별도 확인한다. 편집기에는 콘텐츠를 가리는 가짜 82×76 텍스트 backing을 두지 않는다.
